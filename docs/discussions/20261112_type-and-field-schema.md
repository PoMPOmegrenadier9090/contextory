# 種別とFieldの定義（2026-11-12）

`#`で作る種別に定義を持たせ、ObjectにFieldを入力できるようにした。ここには決めたことと、今回入れた範囲を残す。

## 決めたこと

- 種別の定義は「種別のページ」で行う。名前、色、Fieldの追加・型・並び順・削除をここで扱う。Tanaのsupertagの設定ページを手本にする。
- Fieldの並び順が、そのまま見せる優先度になる。優先度の設定は別に持たない。
- Contextは、すべての種別が最初から持つ特別なFieldとして扱う。見た目と入力は他のFieldと同じにし、推移的な収集と作成位置からの継承は今のまま保つ。削除はできない。
- Fieldは、埋め込みを畳んだ状態では値のあるものを行末に出し、展開した状態ではTitleと本文の間に行として並べる。Object自身のページでは、文書の先頭に常に並べる。
- Fieldの行は文書木の一部にする。カーソル移動や日本語入力を本文と同じ挙動にするためである。保存時に値を本文から切り離す。
- 参照FieldはContextにせず、言及として扱う。「このFieldもContextとして扱う」設定は、必要になったら足す。
- `>`でFieldを書きながら定義する入力は後回しにする。

## 今回入れた範囲

- 保存: `types`（名前、色）、`fields`（種別、名前、型、並び順）、`field_values`（Object、Field、値）を追加した。スキーマはv2で、v1のDBは開いた時に移行する。
- API: `GET /api/next/types`、`PATCH /api/next/types/:name`、`GET /api/next/objects?type=`を追加した。
- Fieldの型: Context、テキスト、参照。テキストと参照は、どちらもインライン内容として保存する。
- 文書木: `objectField`ノードを追加した。Objectの中では`objectTitle objectField* block*`、文書の先頭では`objectField* block+`の並びになる。
- Contextの行: 中の参照チップが、そのObjectのContextになる。自分自身、存在しないObject、循環になる相手は保存時に取り込まない。
- `#`で作ったObjectには、その種別のFieldの行を作成時に並べる。Contextの行には、置かれた場所から継ぐ値を入れる。保存側は、Contextの行があればその内容を正とし、行が無いときだけ置かれた場所から継ぐ。
- Fieldの行ではEnterとTabで次の行へ進む。最後の行では本文の段落を作って移る。行頭のBackspaceでは隣の行とつながらない。
- デモ: ナビゲーションに種別の一覧を、ページ上部の種別名に種別のページへの入口を置いた。Object自身のページにあったContext専用の付与UIは、Contextの行に置き換えた。

## 触ってみた後の変更（2026-11-12）

- 行頭に、開閉のトグルと「開く」ための点を置いた。Tanaに寄せ、マウスの移動を減らすためである。行の右端にあった開閉と「開く」のボタンは外した。点は、畳んだ中身があると輪が付く。
- Fieldと本文の左端を、Titleの文字に揃えた。以前は本文だけがFieldより左に出ていた。
- Taskも他の種別と同じく、行末に`#Task`のタグを出す。行頭のチェックボックスは種別ごとの設定にし、種別のページで切り替える。既定ではTaskだけが出す。スキーマはv3で、`types.checkbox`を足した。
- 畳んだObjectの見えていない行へカーソルが入った時は、進んできた向きへ抜けるようにした。

## 残した近道と未実装

- 畳んだ状態の行末に出るのは、まだContextだけである。他のFieldの値は出ない。
- 日付と選択の型、継承、参照Fieldの値をTimelineへ届ける処理は未実装である。`types.extends`の列だけ先に用意した。
- テキストと参照は、エディタ上の挙動に差がない。参照の候補を種別で絞る指定も無い。
- チェックボックスの表示は種別ごとで、Objectごとには切り替えられない。
- 埋め込みの行末のタグを押しても、種別のページは開かない。タグは擬似要素で描いているためである。
- Contextの行に取り込めない相手（循環など）を書いても、行にはチップが残る。開き直すと消える。
- 種別の定義を変えた直後は、開いていた文書を開き直すまでFieldの行が古いままになる。デモでは種別のページを開いた時点で文書を閉じている。
- 種別の名前は主キーを兼ねる。名前の変更は、種別・Field・Objectの3つの表を書き換える。
- リセット（`PUT /api/next/workspace`）は、ユーザーが作った種別とFieldの定義も消す。
- Contextを付けるAPI（`PUT`・`DELETE /objects/:id/contexts/:targetId`）は残してあるが、開いている文書のContextの行とは同期しない。後から届いた保存が勝つ。
