# 画面の作り直しの計画：選択・右クリック・Timeline・サイドメニュー・入力補助

記録日: 2026-11-16

iPhoneとPCで試して出た要望を、実装の順にまとめる。急ぐのは、PCとiPhoneの両方に関わる「急ぎ」の項目である。実装はこの計画の確認後に始める。

## 要望と原因

| 要望                                   | 今の状態・原因                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 埋め込んだObjectを選択したい（急ぎ）   | Objectのブロックを丸ごと選ぶ手段が無い。Notionのように選んで、消す・切り取る・種別を変えたい       |
| 右クリックのメニュー（急ぎ）           | 無い。書式、新しいObjectの埋め込み、切り取り、将来はViewの挿入を出したい                           |
| Viewの状態を端末間で共有（急ぎ）       | 前回開いたViewと畳んだ行は、端末ごとの`localStorage`にある                                         |
| 説明文が画面を崩す（急ぎ）             | 見出しの下の説明、操作の一覧（`@`・`#`など）、保存先の表示などが、狭い画面で場所を取る             |
| Timelineで内容を読みたい（急ぎ）       | Timelineは一行ずつのTitleで、表と変わらない                                                        |
| 埋め込みのContextのチップ（急ぎ）      | 埋め込んだObjectの中に「Context @View実装」の行が出る。置いた文書と同じContextでも出る             |
| 画面が拡大・縮小できてしまう（iPhone） | viewportで拡大を止めていない。16pxより小さい入力欄に触れると、Safariが自動で拡大する               |
| 上のメニュー（iPhone）                 | 狭い画面では、ナビゲーションが上に横並びになり、何行も取る                                         |
| 文字の装飾ができない（iPhone）         | 太字などはキーボードの操作だけで、iPhoneには入口が無い                                             |
| Timelineで画面が崩れる（iPhone）       | 表が画面の幅を超え、ページ全体が横に伸びる                                                         |
| 埋め込みの開閉が遅い                   | 開閉は文書の変更として保存され、保存のたびに一覧や種別を読み直している。まず計測して原因を確かめる |
| 大きすぎる「＋ Memo」「＋ Object」     | 狭い画面で文字のボタンが2行に折り返す                                                              |

## 1. Viewの状態をDBに置く

前回開いたViewと畳んだ行を、`localStorage`からDBへ移す。どの端末でも同じ状態で開く。

- スキーマをv7に上げ、`ui_state`（key、JSONの値）を足す。キーは今の`localStorage`と同じ（`view:種別:範囲`、`fold:ViewのID`）。
- APIは`GET /api/next/state`（すべて）と`PUT /api/next/state/:key`。`ObjectClient`、Desktop、HTTPのクライアントにも足す。
- 起動時に一度読み、変えたら書く。書き込みは保存の列に並べない。失っても困らない値なので、失敗しても画面は止めない。

## 2. 説明文を減らし、上の帯を小さくする

- 見出しの下の説明（「自由に書く。…」、「ほかの文書でこの日に…」、Fieldの説明など）を消す。必要なものは`title`（マウスを乗せたときの表示）に移す。
- ナビゲーションの操作の一覧（`@`・`#`・Enter・⌫）と保存先の表示を消す。保存先は、ナビゲーションの一番下に小さく残すか、設定へ移す。
- 上の帯は高さ44pxにし、「＋ Memo」「＋ Object」は記号のボタン（`＋`と、Memo用の鉛筆）にする。

## 3. サイドメニューと開閉のボタン

旧Contextoryと同じく、上の帯の左に開閉のボタン（☰）を置く。

- PC：左のメニューを開閉できる。閉じた状態は、端末ごとに覚える（1.のDBではなく`localStorage`）。
- iPhone（幅760px以下）：メニューは画面の上に重ねて出し、項目を選ぶと閉じる。外を触っても閉じる。

## 4. 埋め込んだObjectの選択と、右クリックのメニュー

### 選択

- Objectの行の左にある「・」（開くボタン）の横に、つかむ部分（⋮⋮）を置く。押すと、そのObjectのブロックを丸ごと選ぶ。
- 選んだ状態で、Shift＋↑↓かShift＋クリックで、続くブロックまで広げる。Escで、カーソルのあるObjectを選ぶ。
- 選んだブロックに対して、⌫で消す（文書から外し、Objectをゴミ箱へ移す）、⌘Xで切り取る、⌘C／⌘Vで写す。
- 種別を変える：選んだObjectの種別を、別の種別か、ただの段落（Objectの解除）に変える。種別を変えるには、`ObjectPatch`に`type`を足す。今の種別のFieldの値は、新しい種別に同じIDのFieldが無ければ消える。

### 右クリックのメニュー

右クリック（iPhoneでは長押し）で、場所に合わせたメニューを出す。

- 文字を選んでいるとき：太字・斜体・取り消し線・コード・リンク
- Objectの上：開く、切り取る、写す、種別を変える、文書から外す、ゴミ箱へ移す
- どこでも：ここに新しいObjectを埋め込む（種別を選ぶ）
- 将来：Viewを挿入する

iPhoneの長押しは、Safariの文字選択と重なる。長押しはObjectのつかむ部分だけで受け、本文の長押しはSafariに任せる。本文の書式は5.の入力補助で行う。

## 5. キーボードの上の入力補助（iPhone）

旧Contextoryの帯を、Tiptapのエディタ向けに作り直す。キーボードのすぐ上に浮かべる（`visualViewport`で位置を合わせる）。

- ボタン：太字、斜体、取り消し線、インデントを減らす・増やす、`＋`（4.のメニューを開く）、キーボードを閉じる
- 押してもカーソルとキーボードが残るよう、`pointerdown`を止める。
- IMEで変換中は、ボタンを効かせない。
- PCでは出さない（`hover: none`と`pointer: coarse`のときだけ）。

## 6. Timelineで内容を読む

Timelineを、日付ごとのカードの並びにする。

- Objectの行：種別、Title、作成日時に加え、本文の先頭（数行）を出す。全文はカードを開くと読める。
- 言及：言及している段落・見出し・リスト項目の文をそのまま出し、どの文書かを添える（今の`text`をそのまま使う）。
- 表と違う点：行ではなくカードで、本文を読める。並びは日付の新しい順で、日の見出しを挟む。
- 本文の先頭は、`queryView`の結果に足す（`ObjectTimelineEntry`に`excerpt`を足す）。

## 7. 埋め込みのContextの見せ方

- 置いた文書と同じContext（その文書から引き継いだもの）は、埋め込みの中に出さない。
- それ以外のContextだけを、Titleの後ろに小さな文字（チップではなく、`· View実装`のような形）で出す。
- Contextを変えるときは、Fieldの行を開いて変える。行は、畳んだ状態では出さない。

## 8. iPhoneの細かい修正

- 拡大・縮小を止める：viewportに`maximum-scale=1`を足し、入力欄の文字を16px以上にする（自動で拡大されないように）。
- 表は、表の枠の中だけで横に流す。ページ全体は横に伸ばさない。
- 埋め込みの開閉の遅れ：開閉を保存から外す（開閉は見た目の状態で、版を変えない）か、保存後の読み直しを減らす。計測してから決める。

## 進め方

急ぎの項目から、それぞれ別のcommitにする。

1. 8.（拡大の停止と横の崩れ）と2.（説明文と上の帯）：小さく、すぐ効く
2. 3.（サイドメニュー）
3. 1.（Viewの状態をDBに）
4. 4.（選択と右クリック）：一番大きい。種別の変更を含む
5. 6.（Timeline）と7.（Contextの見せ方）
6. 5.（入力補助）と、開閉の遅れ

検証は、`corepack pnpm check`、`corepack pnpm build`、テスト用のサーバー（5196）での画面の確認、Electronのsmoke、iPhoneでの確認（同じWi-Fiで5196を開く）で行う。

## 決まったこと（2026-11-16）

- 選択して⌫で消したObjectは、ゴミ箱へ移す。
- Timelineのカードは、本文の先頭だけを出す。カードの中では書かない。
- 文書の保存で外れ、ほかのどこにも置かれていないObjectは、ゴミ箱へ移す。間違えて作ったObjectが表に残らないようにするためである。取り消しや、切り取って別の文書へ貼った場合は、保存がゴミ箱から戻し、作成日時とContextは残る。表や「Objectを作成」の窓で作ったObjectは、文書に置かれていないので対象にならない。
- 保存先の表示はナビゲーションから消し、設定の画面（窓）へ移す。設定の窓は、サイドメニューの一番下から開く。バックアップと書き出しのリンクも、ここへ移す。
