# Memoは書いた場所に置き、ContextとDailyの欄で集める

記録日: 2026-11-14

Quick Captureを作り直す前に、Memoをどこに置き、ほかのObjectとどうつなぐかを決めた。結論は次のとおりである。

- Memoは、残したい考えを一つの単位にするObjectとする。地の文は集約しない。
- Memoは書いた場所に置く。Quick CaptureのMemoはDailyに追記する。
- ProjectなどとはContextでつなぎ、そのTimelineに出す。Memoを動かさない。
- Dailyに「この日のMemo」の欄を足し、その日に作ったMemoを、どこに置いたものでも読んで編集できるようにする。

実装はまだ始めていない。最後の節の3点を決めてから進める。

## 地の文を集めず、Memoに書くよう誘導する

最初は「その日に書いた内容を一か所で見たい」という要望から、Dailyに更新したObjectを並べる案や、保存のたびにBlock単位の変更を記録してAIに要約させる案を考えた。

前者では、地の文に書いたメモが拾われない。後者は地の文も拾えるが、差分をすべて見せるのは違う。何が意味のあるメモかを入力時に意識させるのも避けたい。

ここで旧Contextoryのentryを振り返った。考えを一つの単位で残せる点は良かったが、書いたものがすべてentryになる点は良くなかった。そこで、Memoを「自分で選んで作るentry」と位置づけ、地の文は集めないことにした。

| 書いたもの        | 扱い                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| 地の文            | その文書の中だけにある。集約しない                                        |
| Memo              | 考えの単位。どこに書いても、作った日のDailyから読めて、その場で編集できる |
| Task・Projectなど | 管理する単位。Memoを中に埋め込める                                        |

Block単位の変更記録とAIによる要約は、MCPで外のAIから取れれば意義がある。ただ、ユーザーが画面で見られなくても今は困らないので、今回は作らない。

## Memoを一番手軽な選択肢にする

入力のたびに判断させない代わりに、Memoを作る手間を減らす。

- Quick Captureは常にMemoを作る。
- 文書の中で、短い操作で今の行をMemoにできるようにする。`#memo`と打つより短くする。
- 地の文で書き始めて後から残したくなったら、選択して`#`でMemoにする。複数の行を選んで変換する操作は、すでに入れてある。

## Memoは書いた場所に置き、Contextでつなぐ

ProjectとMemoのつなぎ方は二通りあり、目的で使い分ける。

| やりたいこと             | 書き方                                  | 置き場所      | Projectでの見え方 |
| ------------------------ | --------------------------------------- | ------------- | ----------------- |
| Projectの説明として残す  | Projectの文書で`#`から書く              | Projectの文書 | 本文の中          |
| 思いついたことを記録する | Quick Capture。ContextにProjectを入れる | Daily         | Timeline          |

今の実装で、ProjectのTimelineはContextでつながったObjectを集めている（`ObjectStore.timeline`）。DailyにあるMemoでも、ContextにProjectを入れればTimelineに出る。Memoを動かす必要はない。

逆に、置き場所（Placement）は表示する文書を決めるだけである。Projectの文書に書いたMemoは、Contextを入れなければTimelineには出ない。本文の中にあるので、困ることはない。

Projectのページを開いた状態でQuick Captureを起動したら、[設計案](../object-document-design-proposal.md)のとおり、そのProjectをContextの候補として出す。保存前に外せるようにし、画面の裏で勝手に付けない。

## Dailyに「この日のMemo」の欄を足す

Dailyの文書の下に、その日に作ったMemoを、本文を開いた状態で並べる。

- Dailyの文書そのものには入れない。ほかの文書で書いたMemoがDailyの本文を書き換えることはない。
- 欄の中でそのまま編集でき、MemoのページへObjectとして保存する。置いてある文書を開けば同じ内容が出る。保存の競合検出もそのまま効く。
- Dailyの文書に置いてあるMemo（Quick Captureで追記したものなど）は、二重になるので欄に出さない。
- 各Memoに、置いてある文書へのリンクを付ける。

## Projectの本文に載せるのは後回しにする

DailyのMemoを、後からProjectの本文に載せたくなる場面はあると思われる。その場合は、移動ではなく埋め込み（Embed）にする。必要になるまで作らない。

- DBの形では、一つのObjectを複数の文書に置ける（`placements`の主キーが`(host_id, object_id)`）。ただし、二つの文書から同じObjectを読み込み、保存したときに正しく動くかは試していない。
- 移動（Dailyから切り取ってProjectへ貼る）は、今の実装では危ない。文書の保存時に、そこから外れたObjectがほかの文書に置かれていなければ削除する（`savePage`の末尾）。貼り付けより先にDailyの保存が走ると、Memoが消える。移動の操作を作るなら、先にここを直す。

## 決めること

1. 「この日のMemo」に入れる範囲。その日に作ったMemoだけにするか、その日に編集した古いMemoも入れるか。作った日だけにすると、どの日に出るかが分かりやすい。
2. Memo以外の種別も欄に入れるか。その日に作ったTaskなども並べるか。まずMemoだけにし、使ってから決める案がある。
3. 文書の中で今の行をMemoにする操作。キーボードショートカットにするか、行頭の記号を入力ルールにするか。
