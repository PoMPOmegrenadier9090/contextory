# 文書の保存に競合検出を入れる

記録日: 2026-11-14

Desktopからサーバーのデータベースを使えるようにしたことで、MacとiPhoneから同じ文書へ書けるようになった。これまでは後から届いた保存が勝ち、古い画面が新しい内容を上書きしていた。サーバー正本の次に必要な項目として、競合検出を入れた。

## 版は文書全体のハッシュにした

`loadPage`は、編集用の文書木（埋め込んだObjectとField行を含む）のSHA-256を`revision`として返す。`savePage`は`baseRevision`を受け取り、今の版と違えば`PAGE_CONFLICT`で断る。確認と書き込みは同じtransactionの中で行う。

Objectごとの更新日時ではなく文書全体のハッシュにしたのは、次の変更をすべて同じ方法で拾えるからである。

- 別の画面でのhost本文の変更
- 埋め込んだObjectを、そのObjectのページや別の文書から変えた場合
- Field行の値の変更

この画面自身が行うTitleの変更、完了の切り替え、`@`からのObject作成は、開いている文書木に入らないため、自分の保存と衝突しない。種別の定義を変えると文書木のField行が変わり、開いている文書は競合として扱われる。画面は種別のページから戻るときに文書を開き直すので、自分の操作では起きない。

## 画面は上書きか読み直しを選ばせる

断られた文書は、自動では送り直さない。文書の上に知らせを出し、次の2つを選ばせる。

- この画面の内容で上書き：`baseRevision`をnullにして保存する。断られた後も入力を続けていれば、その新しい方を送る。
- 保存されている内容を開く：この画面の変更を捨てて開き直す。

差分を見せて手で合わせる画面は作っていない。必要になったら、上書きの前に両方の本文を並べる形で足す。

## 確かめたこと

- ObjectStoreのテスト：埋め込んだTaskを別のページから変えると、古い版での保存が断られ、内容が変わらないこと。最新の版とnullでは保存できること。
- APIのテスト：古い版での保存が409と`PAGE_CONFLICT`を返すこと。
- ブラウザー：2つのタブで同じDailyに書くと、後のタブに知らせが出ること。「保存されている内容を開く」で前のタブの内容が開き、その後の保存は通ること。古いタブで「この画面の内容で上書き」を選ぶと、その内容がサーバーに残ること。
- Electronのsmokeが通ること。
